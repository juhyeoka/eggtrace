# 매주 농장 영상 올리기

이 Mac의 `문서 > Eggtrace 영상함`에 새 `mp4`, `mov`, `m4v` 파일을 넣으면 됩니다. 원본은 이동하거나 지우지 않아요. 폴더 안의 하위 폴더는 확인하지 않습니다.

자동 확인은 2분마다 실행됩니다. 파일 크기와 수정 시간이 두 번 연속 같고 30초 이상 지나면 새 영상을 준비합니다. 이미 게시한 영상과 내용이 같으면 다시 올리지 않아요. 여러 파일을 넣으면 한 번에 하나씩 처리합니다.

영상은 처리한 주의 월요일 날짜로 묶이고 홈페이지용 영상은 최대 30초로 준비해요. 영상의 위아래와 좌우는 자르지 않고 원본 비율을 유지합니다. 홈페이지의 재생창만 가로 16:9로 두고 남는 여백은 흐린 포스터 배경으로 채워요. 전체 화면 재생은 실제 영상의 원래 비율을 사용합니다. 흐린 배경은 화면 장식으로만 쓰고, 닭 인식·움직임 분석에는 실제 원본 영상만 사용해요. 영상·움직임 표시·분석 자료를 모두 만든 뒤 사이트 설정을 바꾸고 GitHub `main`에 게시합니다. 이후 Render 자동 배포가 끝나면 사이트가 바뀝니다. 준비에 실패하면 기존 영상이 계속 보입니다. 파일 자체의 준비가 실패하면 해당 파일은 10분 뒤에 다시 시도해요.

분석할 때는 먼저 영상 속 새의 윤곽을 인식하고, 그 안에서 잡힌 움직임만 비교해요. 농장 영상에서 확인된 닭을 대상으로 사용하며, 바닥이나 시설물의 움직임을 그대로 합산하지 않습니다. 인식하지 못한 닭까지 모두 센 결과가 아니에요. 작거나 가려진 닭은 빠질 수 있고, 인식이 되지 않은 장면은 비교에서 제외합니다. 전체 사육 마릿수나 닭의 건강 상태를 판단하는 자료로 사용하지 않아요.

인식에는 [Ultralytics YOLO11](https://docs.ultralytics.com/models/yolo11/)의 일반 새 분할 모델을 사용합니다. 모델은 이 Mac의 `~/Library/Application Support/EggtraceWeekly`에 보관하며, 웹에 올리는 파일에는 포함하지 않아요. 영상·인식 모델·처리 설정이 달라지면 새 결과를 만들고, 이전 방식으로 만든 분석을 재사용하지 않습니다.

이번에 제공받은 영상은 원본 35~65초 구간의 전체 화면을 보여줍니다. 해당 구간을 자르지 않고 분석한 `91ba7ed90760` 영상·분석·포스터·장면 사진을 함께 사용합니다. 원본 파일 전체는 그대로 보관해요. 이후 폴더에 넣는 영상은 자동으로 연속 구간을 고릅니다.

수동 준비 명령의 기본값은 `--framing source`입니다. 명시적으로 잘라낼 때만 `--framing landscape`와 `--crop-y`를 사용합니다. 자동 폴더 반영은 영상을 자르지 않습니다.

**이 Mac이 켜져 있고 해당 사용자로 로그인되어 있어야 하며 인터넷 연결이 필요합니다.** 잠자기나 전원 꺼짐 중에는 처리하지 못하고, 다시 실행 가능한 상태가 되면 확인합니다. GitHub 인증은 이 Mac에 설정된 기존 로그인을 사용하며 로그인 정보는 자동 실행 파일에 저장하지 않아요.

## 상태 확인

프로젝트 폴더에서 다음 명령을 실행합니다.

```sh
.venv/bin/python tools/watch_weekly_videos.py --status
.venv/bin/python tools/watch_weekly_videos.py --dry-run
```

로그와 처리 기록은 `~/Library/Application Support/EggtraceWeekly`에 있습니다. `watch.log`에서 마지막 게시 결과나 실패 이유를 볼 수 있어요.

로컬 `main`과 원격 `main`이 다르거나 스테이징한 변경이 있으면 자동 게시를 멈춥니다. 기존 작업을 확인한 뒤 다시 실행하면 됩니다. 자동으로 pull·rebase·stash하거나 다른 작업 파일을 커밋하지 않아요. push가 실패하면 그 커밋을 먼저 다시 보내고 다음 영상을 확인합니다.

## 설치와 첫 영상 등록

이 Mac에는 인식 모델과 실행 환경이 준비되어 있습니다. 다른 Mac에 다시 설치할 때는 프로젝트의 가상 환경에 `tools/requirements-weekly.txt`를 설치하고 [공식 고정 모델 파일](https://github.com/ultralytics/assets/releases/download/v8.3.0/yolo11m-seg.pt)을 위 보관 폴더의 `yolo11m-seg.pt`로 내려받습니다. 허용된 파일의 SHA256은 `eb9a06f63e2206c35d68d839b08c362429ebecf933ad54c1ad68b2fd001c17cf`입니다. 파일이 없거나 해시가 다르면 분석을 시작하지 않습니다.

프로젝트 코드와 첫 영상이 먼저 GitHub에 게시된 뒤 실행합니다.

```sh
.venv/bin/python tools/install_weekly_video_watch.py --dry-run
.venv/bin/python tools/install_weekly_video_watch.py
```

첫 영상을 수동으로 이미 올렸다면 원본을 중복 방지 목록에 등록할 수 있어요. 현재 게시 설정의 원본 해시와 일치하고 원격 `main`까지 게시된 경우만 등록됩니다.

```sh
.venv/bin/python tools/watch_weekly_videos.py --mark-published '/원본/영상.mp4'
```

과거 주를 직접 처리할 때는 `--week YYYY-MM-DD`에 해당 주의 월요일을 지정합니다. 자동 실행에는 이 옵션을 넣지 않습니다.

자동 실행을 멈추려면 다음 명령을 사용합니다. 원본과 게시된 영상은 삭제하지 않아요.

```sh
launchctl bootout "gui/$(id -u)/com.i4company.eggtrace.weeklyvideo"
```

다시 켜려면 설치 명령을 실행하면 됩니다. 이미 실행 중인 작업은 중복으로 시작하지 않아요.
